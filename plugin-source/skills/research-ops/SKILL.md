# Research ops

Help the user set up (or improve) the plumbing behind a research practice.

## The four pillars

1. **Participants** — sourcing, screening, scheduling, paying, re-contact rights, opt-outs.
2. **Tools & data** — repository, transcription, video, prototype hosting, survey platform.
3. **Templates & playbooks** — research plan, brief, screener, consent, interview guide, readout, repo tag schema.
4. **Governance** — consent management, PII handling, retention, ethics review, vendor compliance.

## Participant recruitment options

| Source | Use when | Watch out for |
|---|---|---|
| Your own customer base | You need product-specific behaviour | Selection bias toward power users; re-contact fatigue |
| External panel (User Interviews, Respondent.io, dscout) | You need to recruit fast or non-customers | Panel professionals; screen rigorously |
| Recruitment agency (UXR specialists) | Hard-to-reach segments | Cost; lead time |
| Social media / community posts | Niche communities | Low control; self-selection |
| Askable | Freelance researcher with project-based clients | Pay varies; researcher-led |

See `references/job-search.md` (Askable) and the source guide's UX Research Participant Recruitment links.

## Research repository

A working repo answers three questions in <2 minutes:
1. *Has someone studied this before?*
2. *What did they find?*
3. *Who did they talk to?*

Minimum schema:
- Project (name, dates, owner, decision informed)
- Method, participant count, segments
- Tags: theme, feature area, user type, severity
- Artifacts: report, highlight reel, raw notes (link, not copy)
- Re-contact eligibility

Tools: Dovetail, Condens, Notion (DIY), or Airtable. Condens has good templates and analysis tooling — see `references/blogs.md`.
