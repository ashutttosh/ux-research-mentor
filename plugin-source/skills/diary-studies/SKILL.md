# Run a diary study

Help the user run a study that captures behaviour, context, and emotion across days or weeks — not in a single interview.

## When to use

- You need to understand behaviour that varies by day, mood, or context (commuting, eating, sleeping, using a financial product over a pay cycle).
- You need to capture *in-the-moment* reactions, not retrospective storytelling.
- You're investigating a long process (onboarding, habit formation, recovery).

## Process

1. **Define the prompt(s).** What do you want participants to capture, and when? Time-triggered (every evening), event-triggered (every time you make a purchase), or both.
2. **Pick the duration.** 1 week = behaviour pattern; 2–4 weeks = habit/onboarding; 4–8 weeks = longitudinal change.
3. **Pick the format.** Voice notes, photos, a structured short-form survey, an app like dscout, a private Slack/WhatsApp.
4. **Recruit 10–15 participants.** Expect ~20–30% dropout — over-recruit by ~25%.
5. **Onboard them properly.** A live 30-min kickoff dramatically improves response quality.
6. **Send a daily/weekly nudge.** And a check-in mid-study.
7. **Close with an exit interview** (30–60 min) — this is where the diary entries get interpreted.
8. **Synthesise** with `analyze-research` — diary studies generate a lot of unstructured data; budget time.

## Sample prompt set (financial app, 2 weeks)

```
Daily (evening, time-triggered):
  - One-line: how did money feel today?
  - Voice note (60s): the most memorable money moment today.

Event-triggered (after every purchase ≥ $20):
  - Photo of what you bought.
  - One sentence: why now?
  - Mood 1–5.
```

## Common pitfalls

- Too many prompts → participant fatigue → fall-off after day 3.
- No mid-study check-in → silent dropouts.
- Forgetting the exit interview → you have data but no meaning.
