# Conduct user interviews

Write moderator-ready interview guides and coach the user through running the sessions.

## Process

1. **Confirm the research goal** (use `plan-research-study` first if not done).
2. **Write the guide.** Use the five-block structure below.
3. **Apply Mom Test principles** to every question:
   - Talk about *their life*, not your idea.
   - Ask about specifics in the past, not generics or opinions about the future.
   - Talk less, listen more.
4. **Coach on moderation.** Probes, silence, follow-ups, recording, note-taking.
5. **Plan the analysis up front.** Hand off to `analyze-research`.

## Interview guide structure (5 blocks)

| Block | Duration | Goal |
|---|---|---|
| Warm-up | 5 min | Build rapport, set expectations, get consent on record |
| Context | 10 min | Understand their world, current workflow, last time they did X |
| Deep dive | 20 min | The specific topic — use past-tense, story-based questions |
| Reaction (optional) | 10 min | Show a concept or prototype; observe, don't sell |
| Wrap-up | 5 min | "What didn't I ask about?" Thank, incentive, next steps |

## Question patterns (Mom Test–aligned)

| Use | Don't use |
|---|---|
| "Tell me about the last time you [task]." | "Would you use a product that…?" |
| "What did you try before [current solution]?" | "Do you think this is a good idea?" |
| "Walk me through what happened that day." | "How often do you usually…?" (in the abstract) |
| "What was hard about it?" | "What features would you want?" |

## Moderation rules

- The 5-second silence rule — let them think.
- "And then?" / "Tell me more about that." are your best probes.
- Never finish their sentence.
- Don't react to answers (no "great!" / "interesting!") — it teaches them what you want to hear.
- Record (with consent). Take rough notes; let the recording carry the verbatim.
