# Plan a research study

Help a researcher (or a PM/designer in a researcher's shoes) move from a fuzzy question to a study they can run on Monday.

## Process

1. **Clarify the decision the research will inform.** Ask: who will use this, by when, to make what call? If the user can't name a decision, the study isn't ready to plan — push back and help frame the decision first.
2. **Pick the method.** Use the matrix in `references/methods-overview.md`. Default heuristics:
   - Need *deep understanding of needs/motivations* → 5–8 user interviews.
   - Need *to evaluate a specific design or flow* → 5–8 usability tests.
   - Need *to quantify attitudes or measure prevalence* → survey, n ≥ 100 (read `references/methods-overview.md` for sampling caveats).
   - Need *information architecture* → card sort (15–30).
   - Need *behaviour over time* → diary study (10–15, 2–8 weeks).
   - Need *to compare two designs* → A/B test (powered to significance).
3. **Write the research plan.** Output the structure below.
4. **Brief stakeholders.** Use the briefing template from `references/practical-guides-and-templates.md` (UXinsight UX research briefing template).

## Research plan template

```
Title:
Decision this research will inform:
Research questions (3–5, each tied to the decision):
Method(s) and rationale:
Participants:
  - Criteria:
  - Sample size & rationale:
  - Recruitment source: (see references/research-ops via the research-ops skill)
Timeline (kickoff → readout):
Stakeholders and their role:
Risks and what could change our plan:
Deliverables: (research report, highlight reel, repo entry)
```

## When the user is stuck on method choice

If the user is debating two methods, point them at NN/g's "When to use which research method" and the Meta Research Blog's "Comparing UX Research Methods" — both are in `references/methods-overview.md`. Don't paraphrase the articles; quote at most one short line and link.
