# Analyze research

Take raw qualitative data and produce themes, insights, and a recommendation a team can act on.

## Process

1. **Get the data ready.** Transcripts (or rough notes), tagged with participant ID and method. If notes are messy, run the user research note-taking template first (`references/practical-guides-and-templates.md`).
2. **First pass — observations.** Read everything once. Pull observations (one fact / quote per line) into a flat list. Don't theme yet.
3. **Second pass — affinity mapping.** Group observations into themes. Let themes emerge bottom-up; don't force into pre-set categories.
4. **Third pass — insights.** For each theme: what does it *mean*? An insight = pattern + interpretation + implication.
5. **Prioritise.** Use an impact-vs-effort or impact-vs-confidence matrix.
6. **Write the report** (structure below) and a highlight reel (top 5–8 quotes/clips).

## Insight format

> **Theme:** What people do or feel
> **Evidence:** "[direct quote]" — P3; observed in 6/8 sessions
> **Insight:** Why it matters / what it implies
> **Recommendation:** What to do about it

## Large-scale group analysis

When you have 20+ sessions or a multi-researcher team:
- Split the corpus by researcher, then converge in a 90-min synthesis workshop.
- Use a shared repository (Dovetail, Condens, Notion) with consistent tags.
- Hold a "no new themes" check — if the last 3 sessions added nothing, you have saturation.
- See the source guide's "How to do large-scale group analysis user research" (`references/practical-guides-and-templates.md`).

## Report structure

```
TL;DR (3 bullets)
Decision the research informs
Method & participants (1 paragraph)
Themes (3–7, each with evidence, insight, recommendation)
Open questions (what we still don't know)
Appendix: methodology, participant table
```
